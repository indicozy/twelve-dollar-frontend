Results · the React family

Same React, very different results

Next.js App Router renders React Server Components to a serialized tree, renders that to HTML, and inlines the tree in the page. Remix and TanStack Start render the same components in one pass.

Caching Next.js

Caching buys 7×, then hits a wall

A stored page costs Next.js about 0.40 ms of CPU, the same as Express rendering from scratch. What's left: every new post is a full render on first view, writes go through route handlers (5× Express), pages are 3× larger, and background regeneration and GC stall the single thread, so p99 breaks first.

Results · other JS frameworks

Compiled string renderers lead

Angular builds a server-side DOM per request. Qwik serializes component state for resumability. Solid and Svelte compile components to string building.

Results · other languages

Server templates in other languages

These render HTML and stop: no data for hydration, zero JS. Rust hit the 16,000 cap at 45% CPU. Laravel boots the framework per request under PHP-FPM; Django pays for middleware that Flask skips; Flask is capped by 3 blocking workers.

Why

Every server ran out of CPU, not memory

CPU milliseconds per request at the score. At every server-rendered limit the API used 3-14% of its CPU while the frontend box sat at 95-100%. Score ≈ CPU budget ÷ CPU per request.

Why · where the CPU goes

What each request pays for

Two renders + a payload

Next.js: RSC tree, then HTML from the tree, then a ~28 KB inlined payload, then gzip. 46 KB feed page.

A DOM on the server

Angular builds and serializes a document per request, plus hydration annotations and a transfer cache.

State serialization

Qwik writes ~12 KB of component state for resumability; Nuxt, Remix, TanStack and Solid embed 4-7 KB of data.

Strings

Solid, Svelte, EJS, Askama, Razor: compiled templates that append strings. The cheapest way to make HTML.

Takeaways

What to take from this

The renderer is the bottleneck

With a fast API, the frontend's HTML renderer decides how many users a box can serve. Caching Next.js lifts it from to , still under half of Express.

Framework choice is 6× on the same Node

Defaults matter

RSC payloads, gzip in Node, per-request logging, CSRF tokens, sync workers: each shows up in the score.

Add CPU, not RAM

Every server-rendered stack hit 95-100% CPU with most of its 2 GB unused.
